# 随项目保留的来源元数据

`mapping/0、1、3/segment_mapping.txt` 分别对应 Cargo、Tanker、Tug，从原 `deepship_16k_5s` 复制，内容不变。主线只读取这些映射，再定位外部原始 DeepShip 录音，不需要复制普通切片 WAV。

`split/` 保留已经生成的录音分配表、历史初始候选清单和首次划分协议，迁移项目时一并携带。当前代码只以 `RECORDING_PARTITION.tsv` 决定录音归属；历史初始候选清单和旧协议不再控制片段抽取。旧 denoised 目录及更早的冻结清单已删除，当前划分不保证与删除前一致。

Train/Test/Val 都在所属录音的全部映射候选中选片，排除第 1 段。每类按各录音候选量占比分配名额，以最大余数法取整；录音内部按固定种子排序。QC 拒绝后先在本录音继续补选，候选耗尽才按其他录音剩余候选量分配缺额，最终每类得到 700/150/150 个 PASS/REVIEW 片段。该比例以检查前的映射候选数量为权重，不需对所有备用片段传播；极短录音可能分到 0 个名额，不强制每录音至少入选 1 段。

已有录音归属不重建、不跨集合借片段。若项目没有录音分配表，首次运行按原种子和 70%/15%/15% 规则建立该表及划分协议，不再另外冻结一份 QC 前候选清单。

每次运行的 `SOURCES.tsv` 记录实际检查的候选；运行根目录的 `recording_split_manifest.tsv` 记录实际入池片段。当前入池数量以运行输出为准，不能从项目 `split/` 的历史初始候选清单推断。

外部 DeepShip 原始音频的位置由根目录 `RUN_DATA_GEN_V6.m` 的 `data_root` 配置。移动项目不需要修改映射或清单中的相对录音标识。独立 noise 类由 Wenz 经验谱逐场景合成，不使用 ShipsEar，也不需要噪声录音清单或切片池。
